# Stellar Mission & Test Control System

This repository contains the Stellar Kinetics operations platform and the isolated Rocket Overlay Studio.

## Active development baseline

- Active branch: `development/stellar-ops-v2`
- Stellar Ops version: `2.0.0-alpha.1`
- Default environment: `DEVELOPMENT`
- Service port: `5001`
- Python: `3.10+`

## Start Stellar Ops

```bash
git fetch origin
git switch development/stellar-ops-v2
python -m pip install -r requirements.txt
STELLAR_OPS_ENV=DEVELOPMENT PORT=5001 python -m stellar_ops.app
```

Open the forwarded port or `http://localhost:5001`.

Health endpoints:

- `/health/live` — process liveness and build identity.
- `/health` — database, disk, active run, recording, edge and build status.

## Runtime environments

`STELLAR_OPS_ENV` accepts exactly:

- `DEVELOPMENT` — current single-operator engineering environment.
- `TRAINING` — controlled rehearsal and representative data.
- `PRODUCTION` — reserved for the later production-hardening release.

The current branch is not yet approved for live firing or launch command authority. Field ignition remains simulated and read-only.

## Service boundaries

```text
stellar_ops/                  Mission and test operations platform
app.py + templates/ + static/ Isolated Rocket Overlay Studio
```

Stellar Ops may register exported media as evidence, but it must not import or mutate Studio rendering behavior. Legacy manual broadcast copies are not part of the active V2 baseline.

## Canonical commands

Stellar Ops:

```bash
STELLAR_OPS_ENV=DEVELOPMENT PORT=5001 python -m stellar_ops.app
```

Ethernet edge gateway:

```bash
python -m stellar_ops.edge_gateway --port 9100
```

Development DAQ simulator:

```bash
python -m stellar_ops.edge_simulator --host 127.0.0.1 --port 9100
```

Rocket Overlay Studio, only when explicitly required:

```bash
python app.py
```

## Repository rules

- Runtime databases, evidence, recordings, exports and replay files are excluded from Git.
- Generated bytecode, local secrets and environment files are excluded.
- New Stellar Ops work belongs under `stellar_ops/`.
- The original Studio remains an isolated application boundary.
- Branches predating V2 are historical baselines and are not deployment targets.
